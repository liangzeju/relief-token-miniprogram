### 账户与管理端联动

移动端已接入本地测试邮箱验证码与密码找回，管理端验证令牌后可在“本地测试邮箱”查看消息。测试消息不发送到外部邮箱，10 分钟有效、最多 5 次错误尝试；服务重启清空未完成验证码。测试通过只显示“测试邮箱已验证”，不代表真实邮箱或实名身份验证。生产模式禁用该本地邮箱。

管理令牌现在换取独立 HttpOnly 会话，移动端登录不再覆盖管理员身份，两端退出互不影响。服务重启后需重新登录。默认关闭旧固定角色令牌、旧业务写入和未完成的原型部署/新捐赠；旧数据可只读查询，商城只展示平台采购资源。用户历史申领不删除，正式平台采购和统一资金账尚待接入。

`RELIEF_ENABLE_LEGACY_DEMO=true`、`RELIEF_ENABLE_WALLET_PROTOTYPE=true` 仅用于隔离演示和原型测试，生产环境无效。它们不是正式上线配置，不能绕过未确认的 Gas 政策。正式新操作关闭不额外关闭已有链上余额查询、回执登记和退款接口。

测试：`node backend/test/auth-linkage-browser.cjs` 可自行启动临时后端，验证同浏览器双身份、邮箱验证/找回和退出；`node backend/test/legacy-browser-runner.cjs` 单独验证历史演示兼容，不修改用户当前业务。完整状态以验收矩阵为准。

### 数据故障保护

正式默认模式首次运行不生成演示资金余额。读取已有 `state.json` 时，JSON 或结构损坏会停止启动，不会用示例数据覆盖；发现没有主文件但有 `.tmp` 的中断写入也要求人工检查。写入通过临时文件、刷新与原子替换提交，失败撤回内存变更和幂等结果，健康检查返回 503，后续业务写入及资金操作停止。应先排查磁盘、权限和备份，恢复后重启；不要直接删除损坏数据。现有历史演示记录只读保留，尚未完成统一账本迁移。

### 岗位与采购工作台

开发副本新增 `/operations/`：供方报价、调度库存预留、合同审批人创建可读草案、双方钱包签署同一版本。管理员在管理端签发绑定邮箱和机构的单次岗位邀请，用户在移动账户页绑定钱包并领取；管理员审阅使用 `/operations/?mode=admin`，不能以管理令牌代替业务岗位签约。

岗位、采购命令和合同正文保存在 `DATA_DIR/platform.sqlite`，采用事务与持久幂等；旧 `state.json` 不被自动迁入正式采购。正文和验收标准在服务端计算 UTF-8 keccak256，正文与合同创建同事务提交；缺失或被篡改的正文不能签署。岗位工作台每 10 秒刷新记录，不清空正在填写的表单。

`MONAD_PROCUREMENT_POOL_ADDRESS` 是合同签名域配置，不代表已核验部署或存在可支出余额。未配置时不能创建需签名的合同；测试中使用的地址不能照搬到实际环境。当前没有开放手工确认锁款、交付、验收或付款 HTTP，领域中的这些规则尚待统一账本和新版合约接入。现阶段不是公共 Monad 全业务验收。

测试命令：`node --test backend/test/operator-registry.cjs backend/test/procurement-store.cjs backend/test/platform-service.cjs`；工作台浏览器联测 `node backend/test/operations-browser.cjs`。浏览器使用独立临时服务及测试钱包签名，不广播链上交易。

### 供方报价与公众商城

移动首页、商城和资源详情现已读取同一 `/v1/platform/catalog` 报价源。默认保留参考目录图片；存在有效岗位供方报价时显示精确 MON 起价、该报价的可供量和到达时长，详情列出所有有效报价及编号。没有有效报价时明确显示参考价，不用参考库存冒充真实可采购量。

报价每 5 秒获取，过期、零库存、供方撤权/换绑/角色变更后不再公开；预留 API 也独立检查供方有效性。历史合同及已有预留仍保留原报价和收款钱包供追溯，不因撤权篡改既有约定。行情请求失败时显示不可用；不把旧报价当实时数据。`node backend/test/catalog-browser.cjs` 验证这些真实后端联动，不发交易。

### FIFO 来源账本准备

用户已确认按捐款入池先后使用。`funding-domain.js` 将规范链事件投影为来源账：只在符合任务用途/项目限制且未被其他合同占用的资金中，按区块、交易及日志顺序确定 FIFO。预留/锁款/付款预览不是已使用贡献；实际付款事件才形成捐款到批次的明细。合同结余退回原任务来源，任务结清后回原捐款可用余额，退款只到原钱包；明确列出的 Gas 预留不计贡献。

`funding-store.js` 使用独立 SQLite 事务保存事件、版本和重组更正历史，失败整批回滚，重启重放，重复事件不重计。两模块目前仅接内部规范事件，不核验 RPC、不核验注册授权或验收签名，也没有公开写接口；不应将人工 JSON 输入当作链上事实。尚未接新版合约与资金池页面，不能表示已经完成真实捐赠扣用或授权 Gas 扣费。测试命令：`node --test backend/test/funding-domain.cjs backend/test/funding-store.cjs`。

项目采用“一个后端、两个 Web 端”的结构：

```text
web/mobile  →  面向捐赠者、供应方和公众的移动 HTML5
web/admin   →  面向官方核验、调度、财务、合规和审计人员的桌面管理端
web/operations → 独立岗位账户的报价、采购预留及合同签署
backend     →  统一业务 API、权限、状态机、MON 水印和链上适配
```

## 启动

首次运行请在 `backend` 中执行 `pnpm install --prod --ignore-scripts`（或 `npm install --omit=dev`）。然后在项目根目录运行 `./start.ps1`。脚本会寻找 Node.js，并在 8787 被占用时自动选择其他空闲端口，打印实际访问地址。前台、商城、管理端均由同一个后端提供。

使用 Node.js 24 或更高版本（岗位与采购持久化使用内置 `node:sqlite`）：

```powershell
cd backend
npm start
```

启动后访问：

- 前台首页：`http://localhost:8787/mobile/`
- 前台商城：`http://localhost:8787/mobile/#market`
- 救援任务：`http://localhost:8787/mobile/#tasks`
- 我的账户：`http://localhost:8787/mobile/#account`
- 管理端：`http://localhost:8787/admin/`
- 岗位工作台：`http://localhost:8787/operations/`
- 履约批次：`http://localhost:8787/operations/#fulfillment`
- 管理员采购审阅：`http://localhost:8787/operations/?mode=admin`
- 历史演示申领：`http://localhost:8787/admin/#market-orders`（默认只读）
- 健康检查：`http://localhost:8787/v1/health`

不要直接双击 `web/mobile/index.html` 或用另一个静态端口打开它；这种方式不会启动业务 API。前端源文件在 `web/mobile`，管理端在 `web/admin`，没有被合并成同一个页面。当前文件包是 HTML5 Web 工程，并非可直接导入微信开发者工具的小程序工程。

两端每 5 秒从同一后端更新数据。商品目录由 `backend/catalog.js` 定义；库存、申领单、合同、捐赠和任务保存在 `backend/data/state.json`。旧浏览器 localStorage 不再覆盖服务端数据。连接失败会显示错误，不再自动增加资金/人数或混入前端虚构任务。

商城默认可按类别和名称查找物资及服务、查看有效岗位供方报价或明确标注的参考价，但不允许普通用户申领公共物资。旧申领审批流程只在显式隔离演示中开放。公众商城和岗位采购使用同一有效报价源；验收登记已接入，实物真实性核验与链上付款仍待完成。

岗位工作台已接交付、分批验收登记和财务应付准备，支持按批次独立详情查询。没有可信锁款记录的合同不能交付；只有实际验收数量计入应付。每次交付和验收须有说明及 1..6 件原始附件（PNG/JPEG/PDF，单件不超过 5 MiB），与合同版本、批次及提交人绑定；私有下载核对 SHA256，网络重试不重复存储。附件完整性与格式初检不代表病毒扫描或实物真实性核验，也不代表已链上付款；当前无公共链合约，不能据此进行真实救灾付款或发证。

争议复核按批次分派：管理员选择独立、有效的复核岗位并记录原因，不能代替复核人作结论。复核人只可查看当前获分派批次及其合同原文、已提交材料；改派或撤权后权限失效。复核须提交独立原件与结论，保留原争议验收，按复核通过数量形成应付；同合同其他无争议批次可继续办理。该能力是链下业务登记，不是公共链争议支付守卫。

参考商品价格、参考库存和历史业务项目资金仍为演示值，图片为 AI 生成示意图；有效岗位供方录入的报价单独展示，不等于供方机构或实物库存已获核验。灾情文章标明来源与统计日期；新闻数据不等同于平台演示项目。旧固定角色 token 和 DemoChainAdapter 仅用于单独标记的业务演示，不具备真实钱包后台的管理权限。

## MetaMask 与真实测试网捐赠

前台首页的钱包入口使用 MetaMask 注入的钱包提供器。注册资料保存在后端，密码使用 scrypt 哈希；钱包绑定必须签署单次、限时挑战。邮箱可通过本地测试验证码验证，不发送外部邮件、不代表真实 KYC。手机外部浏览器与 MetaMask App 跳转连接仍待补齐及真机验证。

钱包原型资金池与历史演示账本隔离。原型包含余额、捐赠人注册信息、交易确认过程和按用途分配的页面与接口，但当前没有部署合约，新捐赠关闭，不能把这些原型视为已联通的正式资金流程。新版需实现授权捐赠、用途/项目约束、FIFO 实际支出、合同批次付款及确认索引；姓名、邮箱等个人资料不得写入区块链或返回公共资金接口。

当前使用 Monad 测试网（10143），尚未部署资金池合约。新部署和新捐赠默认关闭；当前原型不足以满足完整的授权、合同、验收及 Gas 规则，不能直接作为最终部署版本。隔离原型测试中的部署字节码及回执核验已实现，但不是上线许可。旧原型联调说明见 [钱包接入与测试网联调](docs/wallet-testnet.md)，使用时以本页和当前决策记录的关闭边界为准。

新版资金基础位于 `contracts/ReliefDonationLedger.sol`：注册签发方的 EIP-712 授权绑定捐赠钱包、金额、用途、项目、费用预留、注册承诺、nonce、截止时间、签发方地址及撤权代次。`backend/funding-receipts.js` 核验单笔规范链回执、运行时代码、交易和事件，再关联私有注册记录生成资金账本输入。它不是已接入页面的持续索引服务。合约仍为抽象基类，费用政策没有默认实现，只有本地测试 harness 可实例化；尚无新版采购锁款、FIFO 实际付款和完整退款流程，不可将测试 harness 部署为正式资金池。

## 当前后端能力

- JSON 持久化的本地开发数据
- 捐赠订单、KYC/合规审核、MON 入账确认
- MON 取得/存入记录和公开水印追踪
- Monad Testnet 交易适配器（当前为 DemoChainAdapter，不转移真实 MON）
- 任务上报、核验和批准
- 公开追踪查询
- PDF 捐赠凭证和项目证书接口
- CORS、角色请求头和幂等键基础处理

上述列表是历史演示适配器的能力，不代表正式链上业务验收。后续按修复清单接入事务型统一账本、新版 Monad 合约、机构角色、真实证据与版本化 PDF；正式流程不再包含人民币到账或银行兑付。当前后端内置的 Bearer token 仅用于显式隔离演示，不能用于生产认证。
