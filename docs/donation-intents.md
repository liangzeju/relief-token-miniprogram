# 捐赠登记快照与回执关联

本模块保存捐赠准备时的历史身份和完整参数，不代表已签发链上授权、已捐款或已履约。已有真实服务的只读列表/详情、管理端页面和条件启用的持久索引器；准备写路由与授权签名仍未启用，当前 8787 也未配置资金池及 RPC。

## 私有快照

`backend/donation-intent-store.js` 使用独立私有 SQLite 文件，按链和资金池固定配置。每条记录包含捐赠 ID、原用户 ID、当时绑定的钱包、注册资料白名单、完整 permit 参数、随机盐和生成时间。姓名、邮箱、组织和本地邮箱验证状态保留历史值；不保存密码、会话或验证码。

同一捐赠 ID 不能覆盖原资料或参数，同一钱包的 nonce 不能换一个 ID 再使用。重复相同准备请求返回原记录，返回对象的修改不会改变数据库。重启和读取时验证结构、关联与承诺一致性。此为私有存储完整性检查，不是针对取得数据库写入权限者的独立防篡改证明，仍需访问控制、加密备份和运维审计。

当前读取先全量核验再筛选，时间复杂度为 O(n)，用于阻止索引字段损坏后隐藏记录；尚未证明适合大规模捐赠吞吐，也未提供生产分页与长期留存治理。不能将本地功能测试当成性能验收。

链上仅提交承诺哈希，不提交姓名或邮箱，也不直接对可枚举的邮箱做无盐哈希。盐和完整快照不应出现在公开资金列表、二维码页面或事件广播中。保留私有快照不意味着身份证明已经成立；`emailVerified` 仍为 false，本地测试邮箱状态单独保存。

## 账户接入

`backend/donation-intent-service.js` 是内部准备适配器，复用实际账户模块的登录会话、来源检查和签名钱包绑定。客户端可选字段仅为请求 ID、用途、项目 ID 和精确 wei 金额。用户身份、钱包、nonce、注册承诺以及费用参数不能由客户端注入。

服务端费用策略回调缺失时拒绝准备，不默认零费用，不假定比例。回调只提供费用预留、费用政策哈希、签发方、撤权代次和截止时间；异步计算后再次检查当前账户，登出或换绑时拒绝写入旧身份记录。该回调只是将来受控策略接入点，不是签名器、Gas 报销器或用户拍板的替代品。

相同请求重试复用同一意向；改金额、用途或项目必须发起新请求。当前钱包变化后不能复用旧请求生成新捐赠。用户仍可读取自己的旧记录，后来绑定原钱包的另一个账户不能继承原用户资料和记录。实际退款授权始终由链上原出资钱包控制，不能把账户读取权限当作退款权限。

## 回执入账

`backend/funding-receipts.js` 的私有 resolver 必须返回原意向的用户、钱包、承诺、链、资金池及完整 permit。旧的仅用户 ID/钱包/哈希三字段结果不再足够。核验逐项对比金额、用途、项目、Gas 预留、nonce、截止、费用政策、授权方和代次，不能仅因当前账户绑定了同一个钱包就认领交易。

同时检查 calldata 的规范 ABI 编码，不接受解析后仍残留额外字节的调用。链上的签名有效性由已固定审核代码哈希的合约执行约束；本模块不会自行用准备记录替代合约授权。核验输出只含资金账本所需的私有用户 ID 和资金事实，不复制姓名、邮箱或盐。

## 已接入的只读业务

管理端 `#wallet-donations` 读取 `/v1/funding/admin/donations`，详情使用 `/v1/funding/admin/donations/:id`；独立管理员会话与 `X-Relief-Actor: admin` 同时有效才可读取。普通用户对应 `/v1/funding/me/donations` 及详情，仅按原用户 ID 读取自己的历史，不按当前钱包重新认领。所有响应 no-store，姓名以外的注册详情在详情页读取；不返回盐、nonce 或密码。

列表有分页、状态/用途筛选和十六进制捐赠 ID 前缀查询，不把邮箱放入查询 URL。意向未入账、当前已记录入账、原入账因重组撤下分开表示；准备与撤下金额不计入账本。已撤下记录保留原交易和区块凭证，当前规范来源记录不混入孤儿事件。详情展示实际逐来源分配、锁款、付款、退款及交易；多人共同支付时只显示本用户实际 FIFO 来源金额。

服务端仅在配置 `MONAD_FUNDING_POOL_ADDRESS` 时打开 `DATA_DIR/funding/donation-intents.sqlite` 与 `funding.sqlite`。未配置时不建这两个库，接口返回未配置、空列表与未知汇总，而不是零余额。不要将旧 `MONAD_POOL_ADDRESS` 原型库改名迁入。原项目启动脚本当前仍清除此配置，避免误开启新账本。

页面始终说明它是已保存投影，不是实时 RPC 余额；完整配置后页面会显示索引是否追上确认高度，但不会直接信任浏览器或未确认 RPC。当前 8787 未配置索引参数，也没有真实捐赠记录或新捐赠签发。读取失败会清除旧展示，退出、权限失效、页面隐藏或迟到响应不能恢复私人资料。O(n) 完整性扫描与对象审计/留存限制仍然存在。

移动端现在通过同源 `/v1/funding/pool` 读取公开白名单汇总，通过 `/v1/funding/me/donations` 及详情读取本人的历史。公开接口只有连接状态、投影版本、已记录金额汇总和捐赠人数，不返回用户、钱包、捐赠 ID、准备金额或注册信息。个人详情的 `accountSummary` 只计算原用户 ID 的资金。

首页区分累计捐赠、全池账本余额与我在池中的余额；个人余额包含仍未支出的 Gas 预留，并单列任务可用、锁定、实际支出和退款。原型关闭时旧钱包脚本不再用旧数据覆盖这些新字段。`#donation/:id` 支持本人详情深链、来源记录和重组撤下凭证；余额下方有分页及用途/状态筛选。

页面可见时每 10 秒重新读取保存账本，不是 RPC 实时同步。未配置或查询失败显示未知，不能用零值替代；私有详情前后复核当前用户，退出、切换用户、隐藏页面和迟到响应不会继续显示前一个用户的资料。完整合约、真实签发、测试网部署和生产索引验收完成后才能开放新捐赠。
