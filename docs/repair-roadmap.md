# 救灾平台修复实施清单

2026-09-04，准备与首批修复阶段，非全量完成。规则见 [decision-log.md](decision-log.md)，验证见 [acceptance-matrix.md](acceptance-matrix.md)。不得将演示资金、本地 EVM 或测试币转账描述为现实救灾发生。

## 1. 交付与实施顺序

保留 Node 后端、移动 H5、桌面管理端和现有图片资产。先修权限与交易核验，再统一身份和业务账、新版合约、平台采购闭环、双端页面、证据与证书，最后公共测试网验收。不新增普通用户购物/公共物资申领业务。

开发使用与原项目核对过的工作副本，回写只同步经过验证的本次变更。先核验原文件哈希并备份，不覆盖业务数据、密钥、他人改动。测试使用随机端口和临时 DATA_DIR，不操作用户正在运行的业务数据。

交付包括合约、数据库迁移、运行文档、逐业务页面、自动测试、真机/测试网记录、未完成项和外部配置清单。只有验收证据才能将项目标为完成。

## 2. 身份、组织、账户与隐私

- 用户与管理员会话分离，API 明确接受的身份；旧演示 Bearer 仅限隔离演示环境。同浏览器两端不能互相覆盖权限。
- 集中校验用户、机构、成员关系、角色、对象范围；列表、详情、导出、事件、证据和 PDF 使用一致的权限规则。管理员不能代验收、代供货。
- 捐赠人看本人资金；供方只操作本机构合同/交付；调度推荐、合同审批签约、验收、财务、独立争议复核职责分离，禁止自审。
- 补注册、登录、退出、找回密码、验证码有效期/尝试/频率、防重放、会话撤销。测试邮箱管理入口受控，生产配置禁止测试认证降级。
- 钱包签署一次性挑战，保留历史地址和出资时快照。新钱包不取得旧钱包资金权；无法证明旧钱包所有权时禁止管理员接管退款。
- 恢复已授权钱包连接，支持刷新、App 返回和账户/网络变化。网络不符禁发；未安装钱包给正确移动引导，不只提示安装桌面扩展。
- 正式捐赠前由平台签发有期限授权，包含注册主体不透明引用、出资地址、用途、项目、金额、费用政策版本和 nonce。合约验证授权且拒绝重放，不能只靠网页拦截。
- 公开白名单与本人可见资料分开。姓名哈希不是匿名保证；二维码不授予原始材料权限，链上地址本身仍可关联。

## 3. 统一业务账、Gas 与自动分配

### 真相与迁移

单实例基线使用 Node 24、事务型 SQLite，保存业务聚合、复式流水、幂等记录、outbox 和区块检查点。不是多实例高可用架构承诺。金额为整数 wei，API 传十进制字符串；单位和数量另有校验，不使用浮点金额。

旧 JSON 账户可迁移，旧会话失效；旧演示合同和资金只读归档，不能变成真实池余额。迁移前备份，验证数量、关系和金额，失败不切换正式入口。

业务审批由后端留痕，资产以确认链上事件为准。pending 不计可用余额；重组重建镜像，不假装撤销已实际完成的链上交易。每条操作具有唯一业务标识与审计记录。

资金科目区分未分配救灾本金、任务可用、合同锁定、待退本金、未用 Gas 预留、报销应付、运营执行钱包余额、已付救灾费用和实际 Gas 成本。预留不是支出，内部调拨不是费用，报销付款不是第二次 Gas 支出。

捐赠 gross = 救灾用途分配 + 费用预算分配。核对池合约和费用执行钱包的各地址流入/流出、应付和余额，不能继续套用没有 Gas 的旧余额公式。无法归属或强制转入资产列对账差异，不伪造捐赠冲平。

### Gas 政策和限制

用户已选择：资金池承担本平台业务 Gas；用户先付后自动报销；从捐款预留。Q01-Q03 未确认前仅开发/测试，不启用实际扣费、报销或部署。

| 费用类别 | 应披露的实际交易 |
|---|---|
| 系统管理 | 部署、授权、暂停/恢复、费用执行地址补充 |
| 捐赠 | 必要链上授权、捐赠、随同执行的分配；同笔交易不得重复计费 |
| 任务预算 | 登记、分配、取消、重新分配 |
| 合同与履约 | 合同登记/锁定/变更、验收和证据摘要上链 |
| 救灾付款 | 物资、人力、民间人员奖励、重建服务支付；本金与 Gas 分开 |
| 证书 | 摘要登记、更正、撤销；单纯生成 PDF 不消耗 Gas |
| 退出与报销 | 退款、Gas 报销转账、对应实际重试 |
| 异常 | 实际上链失败、取消、替换交易的真实费用；未上链请求不算已支出 |

注册/登录/普通链下签名/查询/下载 PDF 没有链上 Gas。RPC、邮件、存储、运费等不是 Gas，未经授权不得混入 Gas 报销。

- 捐赠签名前展示 gross、预留额、最高授权、救灾净额和用户需垫付 Gas；保存费用政策版本。估算过期或费用不足不能扩大用户授权。
- 每次操作检查本次费用、后续必要履约、报销和退款所需预算。缺口时暂停新增操作并告警，不挪用合同锁定款，保留已发生应付。
- 报销仅认可预先授权且关联平台业务的交易，核验 chain/from/to/method/args/value/events/confirmations，按唯一 txHash 去重。收款人为实际垫付人或其有效授权地址。
- 任意外部失败调用不获得报销资格；平台授权流程内的失败记录真实原因与费用，有限重试后人工处理，禁止无上限刷费。
- 费用执行器采用独立受限权限，只能处理白名单报销及费用补充，不能任意转账、改合同或支付采购本金；设置预算、限流、暂停、审计。
- 共用交易费用不得向多个用户重复分摊。费用归属公式、预留上限、余款和启动费用依据 Q01-Q03 冻结，不冒充已有用户授权。
- 按当前 Monad 网络规则核对实际费用，不能用估算值或另一条链的默认公式入账。首笔捐赠之前的部署需独立启动资金。

### 自动分配与推荐

先匹配用途类型和可选项目，再按批准任务紧急度、同级创建顺序和真实缺口分配；净额不包含 Gas 预留。保存算法版本、候选、排除理由、来源金额、执行前后余额。

采购推荐必须考虑可交付的物资数量/服务里程碑、预算、有效报价、库存/队伍能力和 ETA。碎片预算不标作完成采购；资金充足但人员不足时展示人员缺口。

暂停、到期、结束、取消任务停止新增分配。先清理合同义务和争议，再释放余额，保留原用途与来源等待用户退款或重新授权。类型或项目变更不追溯改写原捐赠授权。

## 4. 合约、平台采购与异常状态机

现有未部署合约是原型，不能直接当最终协议。新版采用任务下多合同、多收款人、多验收批次，按来源确认区块/日志顺序分摊，拆分/合并保留父子标识与精确金额。活动队列有界，历史任务不永久占名额。

任务先上报、核验、批准、发布，才接收预算。紧急度有证据和审批，本期不默认授权应急预付或跳过验收。

平台采购：目录/询价 -> 算法推荐和选择理由 -> 人工审批 -> 合同草案 -> 双方签署 -> 链上锁定预算 -> 履约 -> 交付批次 -> 验收 -> 财务支付 -> 证书。普通用户只看目录并捐 MON，不提交公共物资申领。

资源维护类别、单价 MON、计量单位、库存/服务能力、报价有效期、ETA 和资质。签约预留库存/档期，取消释放未履约部分，交付转消耗；民间人员奖励需完成里程碑核验，不能报名即付款。

双方 EIP-712 签署相同 task/标的/价格/数量/预算/收款人/交付/验收/期限/费用版本，校验 chainId、verifyingContract、nonce、有效期。签名是技术证明，不自动代表法律合规签章。

价格、增减量、收款人、交付标准变更必须新版本重审重签；历史已验收批次引用原版本，不扩大原捐款用途。每批验收对应唯一应付，金额由实际数量/合同单价计算，累计不能超预算；不接受客户端任意金额或重复支付。

拒收、部分通过、争议、改判是不同事件。只冻结争议批次，且合约付款守卫生效；独立复核保留新旧证据，其他批次可继续。收款失败保留应付款与锁定预算，不标已付；替代收款地址必须由原权利人授权。

401/403/离线/pending/revert 分开展示。退出/切换身份清除私人缓存。手机网页、MetaMask App 和桌面真实验证，缩小桌面截图不能代替移动连接测试。

## 6. 证据、水印、PDF

交付、验收、实际发放是不同事实。保存批次的数量、时间、组织、签署人、附件、哈希和版本。上传限制类型/大小/权限，原始材料加密保存，公开副本脱敏，不覆盖旧文件。

水印关联捐赠来源、任务、合同、验收、支付和证书；链上仅标识/金额/证据摘要，私人资料不公开。区块链只能证明支付和摘要存在，不能证明照片和实物交付真实性。

每用户/项目/已支付批次一版本 PDF，累计救灾贡献排除 Gas。付款前冻结贡献/证据清单，预生成带稳定 QR 的不可变 PDF，对实际文件字节哈希；清单摘要随付款上链，确认后开放下载。PDF 不包含自身哈希或尚不存在的付款交易哈希，核验网页显示实际交易与文件验证。

未验收、未付、争议未解不签发已完成证书。后续退货、改判、更正、退款和重组保留旧版本并显示新状态；不承诺远程收回已下载 PDF。嵌入中文字体并真机实扫公开 HTTPS 地址。

## 7. 接口与运维

现有 `/v1/wallet/*` 兼容入口最终指向统一业务服务。接口覆盖 auth/admin-auth、tasks、resources、procurements、contracts/signatures/amendments、deliveries/acceptances/disputes、settlements、refunds、gas-quotes/expenses/reimbursements、evidence、certificates、public/verify、events。

写操作统一 actor、organization scope、Idempotency-Key、expectedVersion。`amountWei` 为字符串；业务状态与链上状态独立，不能靠固定百分比判断成功。

队列补 nonce、交易替换/取消、有限重试、死信、确认核验、重组重建和对账。错误哈希不清理恢复记录，不把另一笔同地址交易当本次操作。事件连接限流；部署 HTTPS、CSP、环境密钥、备份恢复、费用不足/链上差异告警。

注册授权签名与费用钱包分权，后台 Token 不等于链上权限。地址/字节码/ABI/网络/角色/暂停策略核验后启用测试网。暂不采用可升级代理；合约变更采用版本化部署、公开迁移和余额处置流程。

## 8. Agent 分工与关卡

身份/API Agent 负责权限与对象范围；账本/合约 Agent 负责资金和费用状态机；页面 Agent 负责双端真实流程；证据/测试 Agent 负责材料、PDF 与黑盒验收；主 Agent 负责接口冻结、整合、备份同步和缺口审查。并行修改范围不能重叠。

关卡：本地修复 -> 迁移/演示归档 -> 本地 EVM -> 同浏览器多角色/真机 -> 公共 Monad 小额全链路 -> 对账/故障恢复/证书核验。未通过必须明确记录，不能用窄范围测试替代整项完成。
